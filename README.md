# Real-Time American Sign Language (ASL) Alphabet Recognition

A computer-vision project that classifies static ASL alphabet hand shapes (A–Z) from webcam frames using MediaPipe hand landmarks and a TensorFlow classifier. A FastAPI service provides inference and sentence-building endpoints, and a browser UI captures webcam frames.

> **Scope:** This project recognizes individual alphabet hand shapes. It does not translate continuous signing, recognize complete signs/words, or model ASL grammar. Letters J and Z involve motion in ASL and may not be reliably represented by a single static frame.

## Frontend-only deployment (no prediction backend)

The browser UI can run inference locally with TensorFlow.js and MediaPipe Tasks Vision. It does not need the FastAPI service for webcam prediction, sentence building, or speech synthesis.

- Original Keras model: `models/asl_model.h5`
- Label order: `models/labels.json`
- Browser model output: `frontend/models/asl_tfjs/model.json` plus its weight shard files, generated by the **Convert ASL model for browser** GitHub Actions workflow.

**Deploy the static frontend:** in Vercel, set the project root directory to `frontend`, choose the **Other** framework preset, and leave build/output commands empty. Deploy only after the model-conversion workflow succeeds and the generated model files are present. Serve over HTTPS so the browser can request webcam access.

Detailed steps: [Frontend-only deployment guide](frontend/README.md).

The Python backend remains in the repository for local API use and development; it is not required by the static frontend. The browser downloads TensorFlow.js/MediaPipe runtime assets from their CDNs and the hand-landmarker task model from Google's hosted model URL.

## Features

- MediaPipe extraction of 21 hand landmarks (63 normalized features)
- Trainable TensorFlow classifier for alphabet classes
- Browser webcam UI and FastAPI prediction endpoint
- Sentence builder (append letter, space, backspace, clear)
- Optional server-side text-to-speech (host audio support required)
- Local webcam inference script
- Health endpoint that reports whether model artifacts loaded

## Requirements

- CPython **3.10**
- A webcam for live use
- For training: sufficient RAM/storage for the selected dataset; CPU works but may be slow
- Camera access requires localhost or HTTPS in modern browsers

The pinned requirements target a CPU-compatible Python 3.10 environment. TensorFlow 2.10 has older platform/Python constraints; do not assume these pins work unchanged on Python 3.11+ or every operating system. The optional Windows DirectML plugin is intentionally not installed by the default requirements because it is platform-specific and can conflict with the baseline environment.

## Dataset preparation and training

Training data is intentionally not stored in this repository. Supply either:

1. `dataset/landmarks.csv` with a `label` column and 63 numeric landmark feature columns, or
2. `dataset/asl_alphabet_images/<LABEL>/*`, with one folder per label and images inside.

For image training, the pipeline extracts hand landmarks from each image. Images where MediaPipe cannot detect a hand are skipped. The default labels are A–Z; the training process writes the exact fitted class order to `models/labels.json`.

Run:

```bash
python training/train_model.py --epochs 80 --batch_size 32
```

Generated outputs:

- `models/asl_model.h5` — trained classifier
- `models/labels.json` — output-neuron label order
- `models/training_metrics.json` — test metrics and per-class report
- `models/training_history.csv` — epoch history

Training datasets remain ignored by Git because they may be large. The trained `models/asl_model.h5` and matching `models/labels.json` are present in this repository branch. The browser conversion workflow generates TensorFlow.js files under `frontend/models/asl_tfjs/`; the static frontend needs those generated files before it can run inference. The Python API also uses the original H5 model when running locally.

The reported metrics must be generated from your own training run. Accuracy depends on dataset quality and split methodology; do not treat any previous number in screenshots or older documentation as independently reproduced.

## Run locally

Start the API and web interface from the repository root:

```bash
uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Open http://127.0.0.1:8000. API documentation is at http://127.0.0.1:8000/docs.

Check service readiness:

```bash
curl http://127.0.0.1:8000/health
```

A reachable service is not necessarily model-ready. Check `model_ready: true` before expecting successful predictions.

For cross-origin frontends, set `ASL_ALLOWED_ORIGINS` to a comma-separated list of trusted origins, for example:

```text
ASL_ALLOWED_ORIGINS=https://your-frontend.example
ASL_MIN_CONFIDENCE=0.60
```

The default allowed origins are localhost development addresses. If the frontend is served by this FastAPI app, same-origin requests do not require CORS.

## API overview

- `GET /` — browser UI
- `GET /health` — API and model readiness
- `POST /predict` — accepts a base64 image/data URL
- `GET /sentence/{session_id}` — current in-memory sentence
- `POST /sentence/action` — append, space, backspace, clear, or speak

Sentence state is stored in process memory and resets when the process restarts. For multi-worker or persistent deployments, replace this with shared storage. Text-to-speech uses the server's audio subsystem; on many cloud hosts audio output is unavailable even if the API is running.

## Security and deployment notes

- Restrict `ASL_ALLOWED_ORIGINS` to the actual frontend origins.
- Image payloads are size-limited and decoded as validated base64.
- Use HTTPS for any public deployment.
- Do not expose debug traces or secrets in client responses.
- Provide the model artifact at deployment time and verify `/health` reports `model_ready: true`.
- The included sentence store is in-memory and not suitable for durable multi-instance sessions.
